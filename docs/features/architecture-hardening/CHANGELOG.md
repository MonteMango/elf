# Changelog — architecture-hardening

## architecture-hardening — raise the consistency floor without changing behaviour

**What:** `GameSession`, `DungeonSession`, and `BattleFightViewModel` no longer carry inline domain rules — reward application, world-turn guarding, roster/run progression, dungeon lifecycle, room-battle rewards, vitals rescale, round execution, and duel pairing each now live in their own DI-injected mutator with an independent unit test. ViewModel logging goes exclusively through the logger abstraction (no raw `print`), enforced by a new `raw_print_banned` SwiftLint rule. `AppRoute.gameSession` carries a `GameID` instead of a whole `Game`, and `AppRoute.calendar` carries no payload at all — both resolve their entity at the destination screen via `SessionRouteView`, with a stale `GameID` popping back instead of crashing. The three near-duplicate inventory-add methods on `GameSession` collapse into one core add path behind thin, signature-preserving shims. `GameStore.player` is now `public internal(set)`, closing the one settable-from-UI gap in an otherwise facade-only mutation model.

**Why:** the primary session facade had grown 251 → 564 LOC (×2.2) after a single feature bolted five more methods onto it — the exact unbounded-growth pattern flagged by the 2026-06-08 architecture review. This is a behaviour-neutral consistency-and-surgery pass to raise the weakest parts of the codebase (session god-objects, raw-print logging, domain models leaking into navigation state) to match the strongest parts, before more features accrete onto the same shapes. See [spec](spec.md) §1–§2.

**How to use:** no new capability is user-facing — this is internal refactor. For a Developer/Maintainer: mutators are resolved via `@Dependency` (e.g. `@Dependency(\.vitalsRescaleMutator)`), each under `Packages/elf_Kit/Sources/DataLayer/Services/<Domain>/`, following the existing `protocol + Default* + +Dependency.swift` pattern. `SessionRouteView`'s `sessionMatchesExpectedGameId(sessionGameId:expectedGameId:)` is the one place that decides render-vs-pop-back for a resolvable route.

**Operational notes:**
- Migration: none — no persisted-data shape changed; this repo is pre-ship, save-format migrations are not a concern per project policy.
- Feature flag / config: none. The new `raw_print_banned` SwiftLint rule is active by default in `.swiftlint.yml`, with an allow-list for logger implementations, the design-system leaf module, and dev-only tools.
- Rollback: revert the diff — behaviour-neutral, no data or API surface to unwind.

**Acceptance criteria delivered:** AC-01 (build/test/lint green, behaviour-neutral) · AC-02 (raw-print lint gate with a plain-language message) · AC-03 (facade-only mutation — `GameStore.player` now `public internal(set)`) · AC-04 (reward-application ordering + world-turn roster-reshuffle invariants, each pinned by a named regression test) · AC-05 (`.gameSession`/`.calendar` resolve at destination; stale `GameID` pops back, covered by `SessionRouteViewTests`) · AC-06 (11 genuine mutator extractions across `GameSession`/`DungeonSession`/`BattleFightViewModel`, each a separate injected type with its own test) · AC-07 (hand-written equality collapsed to one identity/always-true branch per converted route case) · AC-08 (stale doc comment removed, platform line synced) · AC-09 (three inventory-add methods collapsed to one core path + shims).

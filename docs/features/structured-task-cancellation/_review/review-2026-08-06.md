## Findings

### 1. [stage-1, BLOCKING — FIXED] Merge-on-write dropped validator-cleared slots

**file:** `Packages/elf_Kit/Sources/UILayer/Dev/BattleSetup/BattleSetupViewModel.swift:196` (pre-fix)
**AC:** AC-02

The merge loop iterated only the keys present in `validatedItems`. `ElfWeaponValidator` clears a
slot by writing `updatedItems[slot] = nil` into a `[HeroItemType: ItemID?]` dictionary — for a
dictionary whose `Value` is itself `Optional`, subscript-assigning the literal `nil` **removes the
key** rather than storing it as present-with-nil. A cleared slot was therefore absent from the
returned dict, the merge loop never visited it, and the live `selectedItems` kept the stale value.
Two concrete regressions vs. the pre-diff full-dict assignment:

1. Equipping a two-handed weapon no longer cleared an already-equipped shield (and vice versa) —
   the literal AC-02 scenario.
2. Unequip (`selectedItemId: nil`) became a total no-op — `ElfWeaponValidator.swift:29-32` uses the
   same `dict[slot] = nil` clear-by-omission shape.

Independently verified by reading `ElfWeaponValidator.swift` (lines 30, 87, 134, 153 all use the
same `= nil` clear) and reasoning through Swift's dictionary-subscript-nil semantics — confirmed,
not a reviewer false positive.

**Fix applied:** the merge loop now walks `Set(currentItems.keys).union(validatedItems.keys)` and
treats a slot absent from `validatedItems` as cleared (`validatedItems[slot] ?? nil`), matching the
real validator's clear-by-omission contract without reintroducing a full-dict overwrite (AC-06 stays
intact — untouched slots are still skipped by the unchanged-value guard).

### 2. [stage-1, BLOCKING — FIXED] The AC-02 regression test passed against an unreachable payload

**file:** `Packages/elf_Kit/Tests/elf_KitTests/UILayer/Dev/BattleSetup/BattleSetupViewModelTests.swift:136` (pre-fix)
**AC:** AC-02

`release(at: 0, with: [.weapons: …, .shields: nil])` is a dictionary *literal*, where the `nil`
binds to `Value = ItemID?` and therefore creates `.shields` **present with value nil** — the shape
`ElfWeaponValidator` never actually returns for an auto-clear (see finding 1). The test asserted the
right outcome against an input the real validator cannot produce, so its AC-02 coverage was not
real — it would have stayed green even with the bug in finding 1 present, which is exactly what
happened (both bugs shipped together, tests green throughout).

**Fix applied:** the release payload now omits the `.shields` key entirely, reproducing the real
validator's clear-by-omission shape. A new `testUnequip_ClearsTheSlot` test was added, pinning the
second regression (finding 1's unequip-path breakage) that the original suite never exercised.

### 3. [stage-2, non-blocking — DEFERRED] AC-04's literal wording vs. the shipped per-slot design

**file:** `Packages/elf_Kit/Sources/UILayer/Dev/BattleSetup/BattleSetupDisplayModels.swift:29-30` / `spec.md` §5 AC-04
**AC:** AC-04

AC-04 reads "at most one weapon/shield-validation Task is active per hero at a time", but the
Accepted design (ADR-0001) deliberately allows up to two concurrent Tasks per hero (one per slot) —
required for AC-06, proven by `testCrossSlotRapidSelection_BothOutcomesArePreserved`. The invariant
as literally worded does not hold, and no artifact records this as a conscious narrowing (`sad.md`
§1's only decision-override note covers handle *placement*, not the per-hero → per-slot count).

**Disposition:** deferred — recorded in `spec.md` §8 Open questions with owner + due. Not acted on
in this pass (scope limited to finding 1/2 per owner decision).

### 4. [stage-2, non-blocking — DEFERRED] `drainMainActorQueue()` is a magic-number heuristic wait

**file:** `Packages/elf_Kit/Tests/elf_KitTests/UILayer/Dev/BattleSetup/BattleSetupViewModelTests.swift:85-89`

Loops `Task.yield()` 20 times to let scheduled `@MainActor` continuations finish, instead of an
explicit completion signal (e.g. `await task?.value`). The consultant + independent reviewer both
verified this is deterministic in practice today (the resumed continuation has no further suspension
point after the validator call), so not a live flake risk — but the margin is empirical, not proven
by the code's own contract.

**Disposition:** deferred — recorded in `spec.md` §8. Not acted on in this pass.

### 5. [stage-2, non-blocking — DEFERRED] `FakeWeaponValidator.release(at:)` index-shift footgun

**file:** `Packages/elf_Kit/Tests/elf_KitTests/Helpers/FakeWeaponValidator.swift:65-72`

Releasing removes the entry and shifts every later pending call's index down by one; guarded only by
a doc comment, not the API shape. All current call sites release highest-index-first and are
correct, but a future edit that adds/reorders a selection call before releasing could release the
wrong pending call.

**Disposition:** deferred — recorded in `spec.md` §8. Not acted on in this pass.
